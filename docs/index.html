¿Qué es y para qué sirve?

El conector Wazuh permite que el agente de Ruvic consulte alertas de seguridad y el estado de los agentes monitoreados en tu despliegue de Wazuh — listar alertas, ver el detalle de un agente específico, y obtener un resumen general de conectividad.

Una vez configurado, puedes pedirle al agente cosas como:

  • "¿Qué alertas críticas hubo hoy?"
  • "¿Cuál es el estado del agente 001?"
  • "¿Cuántos agentes están conectados?"

Operaciones soportadas:

OperaciónQué hace
cybersecurity.list_alertsLista alertas, con filtro de texto opcional
cybersecurity.get_agentConsulta el detalle de un agente
cybersecurity.get_agents_status_summaryObtiene el conteo de agentes por estado
Dos componentes de Wazuh combinados Este conector habla con el Manager (gestión de agentes) y el Indexer (almacén de alertas, basado en OpenSearch) de forma transparente — necesitas las credenciales de ambos.

Prerrequisitos

  • Un despliegue de Wazuh (Manager + Indexer) accesible por red desde donde corre Ruvic.
  • Acceso de administrador a Wazuh para crear usuarios de solo lectura en ambos componentes.
  • Para pruebas: puedes usar la demo pública oficial de Wazuh, o una instalación propia de prueba.

Configuración en el fabricante

  1. Crea un usuario de solo lectura en el Manager. Usa el sistema RBAC de Wazuh para crear un usuario con permisos de lectura sobre agentes — evita usar el usuario administrativo completo.
  2. Crea un usuario de solo lectura en el Indexer. Con permiso de lectura sobre el índice "wazuh-alerts-*".
  3. Anota los hosts y puertos. El Manager típicamente usa el puerto 55000, y el Indexer el 9200 — pueden estar en el mismo servidor o en servidores distintos según tu despliegue.
  4. Prueba desde línea de comandos (opcional pero recomendado).
curl -sk -u usuario:contraseña -X POST "https://TU_MANAGER:55000/security/user/authenticate?raw=true"

Una respuesta con un token JWT confirma que las credenciales del Manager funcionan.

Permisos requeridos

ComponentePermiso necesario
ManagerRol RBAC con lectura sobre agentes
IndexerLectura sobre el índice "wazuh-alerts-*"

No uses las cuentas administrativas completas de ninguno de los dos componentes.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Wazuh y pulsa Configurar.

Completa los datos del Manager (host, usuario, contraseña) y del Indexer (host, usuario, contraseña) por separado.

Guarda y pulsa Probar conexión.

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: "Conexión exitosa al Manager [host]".

  2. Prueba mínima con el agente.

    Pide algo de solo lectura primero:

    "¿Cuántos agentes están conectados?"

Solución de problemas

Mensaje / síntomaCausa probable y solución
"El Manager rechazó la autenticación"Usuario o contraseña del Manager incorrectos.
list_alerts falla pero get_agent funcionaLas credenciales del Indexer están mal, o el usuario no tiene permiso sobre el índice "wazuh-alerts-*".
Error de certificado TLSMuchas instalaciones de Wazuh usan certificados autofirmados — considera desactivar "Verificar SSL" solo si confías en la red.

Preguntas frecuentes y notas de seguridad

¿El agente puede modificar agentes o alertas?

No. Este conector es de solo consulta — no reinicia agentes, no los elimina, ni modifica reglas o alertas.

¿Por qué se necesitan credenciales de dos componentes distintos?

Porque Wazuh separa la gestión de agentes (Manager) del almacenamiento de alertas (Indexer, basado en OpenSearch) — son servicios independientes con su propia autenticación.

¿Dónde quedan guardadas las credenciales?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlas.

Buenas prácticas Usa cuentas de solo lectura en ambos componentes, nunca las administrativas; y ten presente que el token JWT del Manager expira cada 15 minutos por defecto (el conector lo renueva automáticamente, no necesitas gestionarlo).
